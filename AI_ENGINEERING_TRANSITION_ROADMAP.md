#### Week 5-8: Practical LLM Applications
**Time Commitment:** 15-20 hours/week

**Topics:**

- RAG (Retrieval-Augmented Generation) basics

**Learning Resources:**

- LangChain Documentation: https://python.langchain.com/

**Hands-On Projects:**
1. Build a simple Q&A chatbot using ChatGPT API
2. Experiment with different prompts on Claude
3. Create basic embeddings and similarity search

**Deliverable:** Build a Q&A chatbot using RAG

**Code Sample:**
```python
# Simple RAG implementation
from langchain.embeddings.openai import OpenAIEmbeddings
from langchain.vectorstores import Pinecone
from langchain.chat_models import ChatOpenAI
from langchain.chains import RetrievalQA

# 1. Create embeddings
embeddings = OpenAIEmbeddings()

# 2. Load into vector store
vectorstore = Pinecone.from_texts(documents, embeddings, index_name="docs")

# 3. Create QA chain
llm = ChatOpenAI(model_name="gpt-4")
qa = RetrievalQA.from_chain_type(llm, chain_type="stuff", retriever=vectorstore.as_retriever())

# 4. Query
result = qa.run("What is the meaning of life?")
print(result)
```

from fastapi import FastAPI
from vllm import LLM, SamplingParams
import logging

app = FastAPI()

# Initialize LLM
llm = LLM(model="meta-llama/Llama-2-7b", gpu_memory_utilization=0.8)
sampling_params = SamplingParams(temperature=0.7, top_p=0.9, max_tokens=100)

# Setup logging
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

@app.post("/generate")
async def generate(prompt: str):
    logger.info(f"Generating for prompt: {prompt[:50]}...")
    
    outputs = llm.generate([prompt], sampling_params)
    
    result = {
        "prompt": prompt,
        "generated_text": outputs[0].outputs[0].text,
        "tokens": len(outputs[0].outputs[0].token_ids)
    }
    
    logger.info(f"Generated {result['tokens']} tokens")
    return result

# Run: uvicorn app:app --reload

#### Question 2: RAG System Design
**"Design a RAG system that can answer questions about company documents with 10M pages."**

**Structure:**
1. Clarify requirements (30 seconds)
2. High-level architecture (1 minute)
3. Technical details (2 minutes)
4. Trade-offs (1 minute)

**Sample Answer:**
```
Architecture:

1. DATA INGESTION
   - Parse PDFs, documents with Apache Tika
   - Split into chunks (512 tokens, 20% overlap)
   - Version all changes (DVC)

2. EMBEDDING & INDEXING
   - Embed chunks using OpenAI embeddings (768-dim)
   - Store in Milvus (distributed vector DB)
   - Index with IVF_FLAT for 10M+ scale
   - Add metadata for filtering

3. RETRIEVAL
   - User query → embed → semantic search
   - Return top 10 similar chunks
   - Re-rank using cross-encoder

4. GENERATION
   - Format retrieved chunks into context window
   - Use GPT-4 with system prompt
   - Return answer with citations

5. MONITORING
   - Track retrieval accuracy (NDCG)
   - Monitor generation quality (human feedback)
   - Alert on drift

Trade-offs:
- Accuracy vs latency: Re-ranking adds 500ms
- Cost vs quality: GPT-4 vs GPT-3.5 = 10x cost
- Freshness vs scale: Daily indexing vs real-time
```

SERVING ARCHITECTURE:

4. SCALING

   - Regional replicas for latency

5. MONITORING
   - Latency percentiles (p50, p99)

   - Cost per inference
   - Cache hit rate

Expected Performance:
- Cache hits: <10ms

**"How would you ensure data quality for an LLM training dataset with 1 billion documents?"**

```
DATA QUALITY FRAMEWORK:

1. VALIDATION LAYER
   - Schema validation (with Great Expectations)
   - Data type checks
   - Null/missing value handling
   - Outlier detection

2. FILTERING PIPELINE
   - Remove duplicates (fuzzy matching)
   - Language detection
   - Toxicity/bias filtering
   - Quality heuristics (length, formatting)

3. MONITORING
   - Data quality metrics tracked in MLflow
   - Version all filtering rules
   - Track what percentage of data is filtered

4. HUMAN REVIEW
   - Sample 10k documents monthly
   - Have human annotators rate quality
   - Use feedback to improve filters

5. TESTING
   - Unit tests for each filter
   - Integration tests on sample data
   - A/B test different filtering strategies

Tools:
- dbt for transformation
- Great Expectations for validation
- DVC for data versioning
- MLflow for metrics tracking
```

5. FAILURE ANALYSIS

   - Monthly analysis of failure patterns

- Quality metrics by category
